# Testing

CalmCSS uses focused unit tests, JSON conformance cases, generated Tailwind
parity suites, render parity checks, and Go wrapper tests.

## Quick Check

```sh
zig build test
npm run conformance
npm run parity:plugins
go test ./...
```

## Full Local Suite

```sh
zig build test
node scripts/conformance.mjs
npm run parity
npm run parity:sets
npm run parity:theme
npm run parity:utility
npm run parity:variant
npm run parity:official
npm run parity:plugins
npm run parity:render
npm run parity:web-demo
go test ./...
```

## What Each Suite Covers

The Zig tests cover extraction, variants, chunk replacement, plugin-class
output, and the no-snapshot production build path.

The Node conformance script checks a JSON case suite against the real CLI.

The parity script compiles candidates through `tailwindcss@4.2.4` and CalmCSS,
then reports exact normalized CSS matches for core utilities. Plugin classes are
tracked separately in `test/plugin_candidates.json` with an oracle that loads
`@tailwindcss/forms` and `@tailwindcss/typography`; the tracked plugin output
snapshots are generated by `scripts/generate-plugin-snapshots.mjs`.

`npm run parity:sets` compares multi-class golden outputs from Tailwind's own
compiler, which catches cascade-order bugs that single-utility snapshots cannot
see.

`npm run parity:theme` checks CSS-first `@theme`, `@theme reference`, and
`@theme inline` behavior for custom colors, spacing, radius, font, easing,
breakpoints, text sizes, leading, tracking, prefix handling, and demand-driven
variable emission, including `@theme default`, `@media theme(...)` wrappers, and
leading and trailing important modifiers.

`npm run parity:utility` checks static and functional CSS-first `@utility`
definitions, variants, duplicate definitions, special characters, single-word
names, simple top-level and nested `@apply`, authored CSS `@apply`, nested
authored selector and at-rule blocks, selector-list nesting, `@tailwind
utilities` directive placement, `@apply` typed-property side effects, authored
`--spacing(...)` and `--theme(...)` CSS functions including theme color opacity
modifiers and initial-fallback injection, authored `--alpha(...)` CSS functions,
legacy authored `theme(...)` CSS functions in declarations and at-rule preludes
including color opacity modifiers, recursive `theme(...)` references in
CSS-first theme values, simple authored `@custom-media` aliases with
theme-backed media queries, and at-rule prelude `--theme(...)` inlining.

The utility parity suite also checks the `tailwindcss/utilities` import
entrypoint including `important`, the `tailwindcss/preflight` and demand-driven
`tailwindcss/theme` import entrypoints including `theme(static)`, the full
`tailwindcss` import shorthand for base/theme/utilities, prefixed Preflight
theme variables, `@reference "tailwindcss/theme"` fallback variables, authored
`@apply` utility ordering, `@reference "tailwindcss"` for theme-backed authored
`@apply`, nested custom-utility expansion through `@apply`, full-import authored
`@apply` theme-variable emission, prefixed full-import theme variable
references, alpha color fallbacks, custom and static `--animate-*` theme
keyframes, snapshot-backed `content-[...]` expansion in authored `@apply`,
`@source inline(...)` inclusion/negation with brace expansion, `--value(...)`
resolution, and property-order sorting against the official compiler, including
prefix handling, slash modifiers, ratio values, leading and trailing important
modifiers, prefixed `group-hover`/`peer-hover` marker selectors, unprefixed
CSS-variable lookup inside prefixed arbitrary `theme(...)` candidates, and
`--spacing(...)` shorthand.

`npm run parity:variant` checks body-less CSS-first `@custom-variant` selector
and media wrappers, plus selector-body and at-rule-body variants that use
`@slot`, including nested, mixed selector/media, and parallel branches, legacy
`@variant` aliases, authored CSS `@variant` blocks for built-in, arbitrary
selector, ARIA/data, and container variants, composition with static custom
utilities, selector-list wrapping for authored selector variants, and
`group-*`/`peer-*` variants.

`npm run parity:render` renders checked HTML snippets in headless Chrome with
official Tailwind CSS and CalmCSS, then compares selected computed styles across
desktop and mobile widths.

`npm run parity:web-demo` runs the same render checks through the actual
`web/index.html` WASM demo and its preview iframe, so browser-demo regressions
are caught directly.

The larger official corpus is mined from candidate-like strings in Tailwind CSS
source tests by `scripts/generate-core-snapshots.mjs`. It covers 3,336
Tailwind-derived core candidates. Expanding these suites is the intended path
toward proving broader compatibility.

## Optional Official Source Checks

Some parity and snapshot-generation scripts need a local Tailwind CSS source
checkout. Point them at the source test directory explicitly:

```sh
CALMCSS_TAILWIND_SRC_ROOT=/path/to/tailwindcss/packages/tailwindcss/src npm run parity:sets:official
CALMCSS_TAILWIND_SRC_ROOT=/path/to/tailwindcss/packages/tailwindcss/src npm run parity:official-css-context
CALMCSS_TAILWIND_SRC_ROOT=/path/to/tailwindcss/packages/tailwindcss/src npm run generate:core-snapshots
```
